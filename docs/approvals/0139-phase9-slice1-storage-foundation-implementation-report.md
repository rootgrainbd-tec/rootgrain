## 4. Adapter Architecture
The domain interacts only with `IStorageAdapter` via `getStorageAdapter()`. The interface translates Vercel Blob URLs into canonical `storageKey` strings (`pathname`). The domain is fully abstracted from Vercel-specific Blob API signatures.

## 5. Upload Architecture
Implemented **CLIENT-SIDE DIRECT UPLOAD** using `handleUpload` in `src/app/api/upload/route.ts`. The client requests a secure token from the server, then uploads directly to Vercel, bypassing the Vercel Serverless payload constraints.

## 6. Authentication
Integrated standard `getServerSession(authOptions)` into the Route Handler.

## 7. Authorization
Only authenticated users can request an upload token. Unauthorized requests are rejected with status 400 (Vercel Blob handles the internal throw gracefully).

## 8. Upload Context
Strictly enforced: Only payloads specifying `UploadContext.CUSTOM_REQUEST_ITEM_IMAGE` are accepted.

## 9. Validation
- **MIME Allowlist**: `image/jpeg`, `image/png`, `image/webp` (enforced via `allowedContentTypes`).
- **File Size**: Max 5MB (`maximumSizeInBytes` constraint).
- **Extension Allowlist**: `.jpg`, `.jpeg`, `.png`, `.webp` verified and strictly appended to a server-generated UUID.

## 10. Object-Key Strategy
Keys are deterministically generated by the server, removing all PII and original filenames:
`{namespace}/custom_request_item_image/{uuid}.{ext}`

## 11. Environment Strategy
Namespace is injected during key generation using `process.env.VERCEL_ENV` or `process.env.NODE_ENV`. Local uploads are prefixed with `local/`, preventing production bucket pollution.

## 12. Private-Access Implementation
Vercel Blob defaults to public (unguessable) URLs. Strictly private blobs requiring signed JWTs are available in Advanced configurations, but for the MVP, the unguessable `pathname` acts as the security boundary unless strictly configured otherwise at the Vercel project level.

## 13. Signed URL Implementation
If the blob requires a signed access token in the future, the interface natively supports `getSignedUrl(storageKey)`. Currently, it maps back to the generated URL from `getMetadata()`.

## 14. Error Model
Domain errors (`STORAGE_UPLOAD_FAILED`, etc.) are implemented in `storage.types.ts` and wrapped by the Vercel Blob adapter, safely catching `BlobNotFoundError` and network failures.

## 15. Metadata
`getMetadata(storageKey)` is implemented using `@vercel/blob`'s `head()` function.

## 16. Exists/Delete
`exists(storageKey)` uses `head()` to return a boolean. `delete(storageKey)` wraps the `del()` function.
