# 1 Executive Summary
A comprehensive read-only audit of the RootGrain production repository was performed for the Phase 2 upgrade. Key findings show that while the core cart/checkout engine and initial email infrastructure are solid, substantial components for MTO (Made-To-Order), Custom Orders, and Financial Ledgers are either missing or fundamentally incomplete. The existing `PaymentRecord` table is completely unused. There is no WhatsApp integration, no price revision tracking, and no `Notification` model.

# 2 Current Architecture
- Frontend: Next.js App Router (React)
- State: Zustand (`useCartStore.ts`)
- Database: PostgreSQL via Prisma ORM
- Email: Resend + PDFKit (`src/lib/email.ts`, `src/lib/pdfGenerator.ts`)
- Component Library: Radix UI / shadcn

# 4 Current Order Flow
- User clicks Add to Cart → Cart state updates in `useCartStore`
- User proceeds to Checkout → Order is created with `OrderStatus.PENDING_ADVANCE`
- `sendOrderConfirmationEmail` fires and attaches a PDF generated by `pdfGenerator.ts`
- Status updates (e.g. `CONFIRMED`) happen via Admin dashboard modals which update the scalar `advancePaid` field.

# 5 Current MTO Flow
- MTO is currently flagged via `inStock: false` on `Product`.
- Triggers `InquiryDialog.tsx` which submits to the `Inquiry` table.
- `Inquiry` does not automatically convert into an `Order`. Admin must handle it manually. There is no dedicated CUSTOM ORDER main navigation form.

# 6 Current Payment Flow
- `advancePaid` is used to track the advance amount.
- `balanceDue` is calculated in the frontend or at checkout.
- `PaymentRecord` schema exists but `0005R2` audit proved it has 0 records.
- Payments overwrite `advancePaid` rather than appending a ledger record.

# 7 Current Invoice/PDF Flow
- PDF is generated via `src/lib/pdfGenerator.ts` and attached to the confirmation email.
- HTML invoice is available at `/checkout/invoice?order=...`.
- *Mismatch Issue:* The PDF layout and HTML layout are maintained entirely separately, leading to discrepancies in fields and styling.

# 8 Current Email Flow
- `src/lib/email.ts` sends emails via Resend.
- Templates are built via `getBaseTemplate`.
- `sendOrderConfirmationEmail` attaches the PDF.
- `sendOrderStatusUpdateEmail` sends transition emails (but NO PDF).
- Safe fire-and-forget logic with `try-catch` exists.

# 9 Current WhatsApp Capability
- Does not exist. Only social sharing `<a>` tags exist in `ProductActions.tsx`.
- No API provider is installed in `package.json`.

# 10 Current Notification System
- Does not exist. No `Notification` model in Prisma.

# 11 Current Wishlist Flow
- API `POST /api/user/wishlist` calls `userService.addWishlistItem`.
- There is no logic to detect an existing item and remove it (toggle).
- Results in Unique Constraint errors on repeated clicks or always shows "Added to wishlist!".

# 12 Current Customer Profile Flow
- Profiles exist, but no Document Vault or interactive notification panel exists.

# 13 Current Admin Order Flow
- Located in `src/app/(storefront)/admin/orders`.
- `OrdersTable.tsx` renders a basic list with an Export CSV button.
- Missing: Text search, MTO filters, Status filters, Order Notes.

# 14 Current Database Models
- `Order`: Overloaded with `advancePaid` and `balanceDue`.
- `Inquiry`: Basic fields (`name`, `phone`, `message`). Disconnected from users.
- `PaymentRecord`: Exists but completely inactive.
- Missing Models: `CustomRequest`, `PriceRevision`, `OrderEvent` (Timeline), `Notification`.

# 15 Current API/Service Map
- Wishlist: `api/user/wishlist/route.ts` → `userService.ts`
- Admin Orders: `app/actions/admin.ts` (`updateOrderStatus`) → `orderRepository.ts`
- Email: Triggered implicitly after DB inserts.

# 16 Known Bugs + Root Causes
1. **Wishlist always says "Added":** Root cause is `handleAddToWishlist` only issues POST requests and `userService.addWishlistItem` does an unconditional insert.
2. **Existing invoice/email PDF mismatch:** Root cause is `pdfGenerator.ts` uses strict PDFKit coordinates which do not match the DOM logic in `/checkout/invoice/page.tsx`.
3. **MTO Limitations:** MTO is treated as an `Inquiry` rather than an `Order` flow, lacking financial conversion.

# 17 Phase 2 Gap Analysis
**A. Shopping UX**
- CURRENT: Add to cart only.
- TARGET: Buy Now integration without duplicating checkout.
- GAP: Needs Buy Now action that redirects immediately to checkout with a 1-item payload.
- RISK: State corruption if Buy Now overwrites existing cart unintentionally.

**B. Wishlist**
- CURRENT: Add-only.
- TARGET: Toggle functionality.
- GAP: Update API to support DELETE, or make POST act as a toggle.

**C. Custom Order & MTO**
- CURRENT: `Inquiry` model.
- TARGET: `CustomRequest` with image upload, autofill, and conversion.
- GAP: Need new model, form UI, and admin conversion API.

**D. Financial Architecture**
- CURRENT: Scalar `advancePaid`.
- TARGET: Append-only `PaymentRecord` ledger.
- GAP: Admin UI needs to create `PaymentRecord` entries. `balanceDue` must be calculated dynamically.

**E. Price Revision**
- CURRENT: Price is fixed.
- TARGET: Trackable price adjustments.
- GAP: Need `PriceRevision` model and Admin UI.

**F. Order Status**
- CURRENT: Standard statuses.
- TARGET: Add `READY` status.
- GAP: Update Prisma `OrderStatus` enum.

# 18 Regression Risk Matrix
| Feature | Affected Systems | Regression Risk | Mitigation |
|---|---|---|---|
| Buy Now | Checkout, Cart | Medium | Isolate Buy Now state from `useCartStore` if possible |
| Payment Ledger | Order Subtotal/Total | High | Ensure dynamic summation `total - SUM(payments)` is strictly tested |
| WhatsApp | Checkout speed | Low | Run WA notifications asynchronously (fire-and-forget) |
| Price Revision | Invoice / PDF | Medium | Ensure PDF generator dynamically recalculates based on revisions |

# 19 Migration Risk
- As proven in Audit 0005R2, all current production orders are TEST DATA.
- `PaymentRecord` has 0 rows.
- **Migration Risk is LOW.** Schema expansions (adding `READY` status, requiring `PaymentRecord`) are safe.
