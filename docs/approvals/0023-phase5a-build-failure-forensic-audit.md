# 0023 Phase 5A: Build Failure Forensic Audit

**Status:** PROPOSED — AWAITING HUMAN REVIEW

## 1. Build Failure Summary

`npm run build` exits with code 1 during the static page generation phase. The build compiles TypeScript and produces optimized chunks successfully, but fails during prerendering when Next.js attempts to server-render pages that import `@/lib/auth` → `@/lib/prisma`, which requires a valid `DATABASE_URL`.

The root cause is a **local environment configuration issue**: the file `.env.production.local` contains empty string values for critical environment variables (`DATABASE_URL=""`, `NEXTAUTH_URL=""`, `DIRECT_URL=""`). Per Next.js environment variable loading precedence, `.env.production.local` overrides `.env` during production builds, causing the PrismaClient to receive an empty database URL.

## 4. Stack Trace Evidence

The stack trace shows the error occurs at **module evaluation** time — when `PrismaClient` is instantiated with `new PrismaClient()`. The PrismaClient constructor reads `DATABASE_URL` from `process.env` and attempts to parse it as a URL. When `DATABASE_URL=""`, this triggers `ERR_INVALID_URL`.

The error cascades through the Turbopack SSR runtime:
1. `instantiateModule` → `getOrInstantiateModuleFromParent` → `esmImport`
2. This hits the `@/lib/prisma` module, which calls `new PrismaClient()` at import time
3. PrismaClient fails to parse the empty connection string

### Environment Variable Loading Order (Next.js production build)

Per Next.js documentation, `npm run build` sets `NODE_ENV=production`, and env files are loaded in this priority order (highest first):

1. `.env.production.local` ← **OVERRIDES ALL** (contains `DATABASE_URL=""`)
2. `.env.local`
3. `.env.production`
4. `.env` ← (contains valid `DATABASE_URL="postgresql://postgres:postgres@127.0.0.1:54325/postgres"`)

Because `.env.production.local` sets `DATABASE_URL=""`, the valid value in `.env` is overridden with an empty string.

## 9. Database/Prerender Analysis

The failing pages are **Server Components** that call `prisma.order.findMany(...)` or `getServerSession(authOptions)` (which imports `PrismaAdapter(prisma)`) during prerendering. During `next build`, Next.js attempts to statically generate these pages, which triggers the Prisma module evaluation, which fails because `DATABASE_URL` is empty.

This is a **data/prerender** issue compounded by an **environment configuration** issue:
- The pages perform database queries at build time (prerender)
- The build environment lacks valid database credentials
- On Vercel (production), these pages would be dynamically rendered with proper env vars injected at runtime
- Locally, the `.env.production.local` stub file (created by Vercel CLI) overrides the working `.env` values

## 10. Root Cause Classification

**PRIMARY: E — DATA / PRERENDER**

The immediate cause is that server-rendered pages attempt database access during `next build` prerendering, and the build environment does not have a valid `DATABASE_URL` due to `.env.production.local` overriding `.env`.

**SECONDARY: C — ENVIRONMENT / DEPENDENCY**

The `.env.production.local` file was created by the Vercel CLI with empty placeholder values. This is a local development environment artifact, not a code defect.

**NOT: A — PHASE 5A RELATED**

Phase 5A files are not in the import chain of any failing route. The failure predates Phase 5A by 11 days.

## 11. Impact Assessment

- **Phase 5A implementation:** NOT AFFECTED. All 10 tests pass, TypeScript compiles cleanly, and the 13/13 acceptance criteria remain verified.
- **Production deployment (Vercel):** LIKELY UNAFFECTED. On Vercel, environment variables are injected at runtime and `.env.production.local` does not exist in the deployment artifact. The pages that fail locally would be dynamically rendered with proper credentials.
- **Local development build:** AFFECTED. `npm run build` cannot complete locally due to the empty env override.

## 12. Recommended Remediation

### Option A: Remove `.env.production.local` (Recommended)

Delete the Vercel CLI-generated stub file that contains empty values. This allows `.env` to provide valid local credentials during local builds.

- **Risk:** Low. The file is a local CLI artifact with no production impact.
- **Reversibility:** Fully reversible (re-run `vercel env pull`).

### Option B: Populate `.env.production.local` with valid values

Fill in the empty variables with valid local database credentials.

- **Risk:** Medium. Must ensure no production credentials are stored locally.

### Option C: Mark failing pages as dynamic-only

Add `export const dynamic = 'force-dynamic'` to the affected pages to skip prerendering.

- **Risk:** Low code change, but modifies non-Phase-5A source files.

### Option D: Accept build failure as local-only

If the production Vercel deployment succeeds independently (which it likely does), accept that `npm run build` is not expected to succeed locally without proper env configuration.

- **Risk:** None. But reduces local verification capability.
